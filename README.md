# 애즈폼

광고 캠페인 주문·승인, 오퍼월 참여, 포인트 적립, 대행사 충전과 실행사 수익을 한 PC에서 체험하는 로컬 MVP입니다.

[초기 Bizpop 분석 및 MVP 구축 계획](docs/bizpop-benchmark-and-mvp-plan.md)

## 실행

1. Node.js 22.13 이상이 설치된 PC에서 `start.cmd`를 열거나 프로젝트 폴더에서 `npm start`를 실행합니다.
2. [http://127.0.0.1:3063](http://127.0.0.1:3063)에서 애즈폼을 엽니다.
3. 로그인 페이지의 테스트 버튼에서 최고관리자, 실행사, 대행사, 광고주, 참여자를 선택하거나, 회원가입으로 참여자·광고주 계정을 직접 만듭니다.

설치할 npm 패키지가 없습니다. 로컬 서버가 처음 실행될 때 `data/demo.sqlite`를 만들며, 승인·잔액·배경 설정은 서버를 다시 실행해도 유지됩니다.

메신저 공유 카드는 HTML의 Open Graph 태그에 설정되어 있습니다. 공개 HTTPS 주소로 배포한 경우 서버 시작 전에 `ADSFORM_PUBLIC_ORIGIN`을 해당 주소의 출처로 설정하면 공유 이미지와 페이지의 주소가 공개 주소로 표시됩니다. 이 환경 변수는 메타 태그의 URL을 설정합니다. 카카오톡에서 카드를 읽으려면 페이지와 공유 이미지가 외부에서 접근 가능해야 합니다.

## 확인 흐름

- **계정별 대시보드** — 로그인 후 좌측 메뉴에서 해당 역할의 기능을 사용합니다. 모바일에서는 상단 메뉴 버튼으로 좌측 메뉴를 열 수 있습니다. 메뉴 하단에는 프로필과 메인으로 이동하는 버튼이 있습니다.
- **PC 화면** — 최고관리자 좌측 메뉴 → PC 배경 → 기존 감성 배경 5종과 광고 테마 5종, 총 10종 중 하나 선택. 광고 테마는 광고 기획 스튜디오·콘텐츠 촬영 스튜디오·도심 속 브랜드 광고(실사형), 브랜드 쇼룸·캠페인 성장 가든(일러스트)으로 구성됩니다.
- **문의 접수** — 메인페이지 문의하기 버튼으로 문의를 남길 수 있습니다. 최고관리자는 좌측 메뉴의 문의 내역에서 내용을 확인합니다.
- **실행사 수익** — 실행사 → 하위 대행사 등록 → 생성한 대행사로 일반 로그인 → 충전 신청 → 최고관리자로 승인 → 실행사 수익 원장 확인
- **수익률** — 최고관리자 → 계정·수익률 → 전체 기본값 또는 개별 실행사 값 설정. 빈 개별 설정은 기본값을 사용합니다.
- **광고·오퍼월** — 광고주 → 주문 등록 → 최고관리자 승인 → 참여 시작으로 자리 확보 → 답변 제출 → 퀴즈 자동 적립 또는 설문 검수 후 적립

미션 자리는 최대 10분간 유지되며 집행 마감 시각을 넘기지 않습니다. 캠페인 기간이 끝나면 미제출 예약은 효력을 잃습니다. 제출된 응답의 검수가 모두 끝난 뒤 미집행 예산이 자동 반환됩니다. 주문 상세에서 승인 집행액과 반환액을 확인할 수 있습니다.

충전 승인 시 대행사에는 승인액 전액이 들어가고, 실행사 수익 원장에는 승인액 × 당시 수익률을 원 단위로 내림한 금액이 별도 반영됩니다. 기본 수익률은 7.5%이며, 과거 승인 건은 승인 당시 적용률을 유지합니다.

## 고도화 기능 (2026-11-10)

- **역할별 대시보드** — 광고주·대행사·실행사는 잔액 히어로, KPI(진행 캠페인·오늘 승인·검수 대기·승인율), 14일 참여 추이 차트, 캠페인 상태 도넛, 캠페인 현황 표, 일별 집행 금액, 잔액 내역, 예산 사용 구성을 봅니다. 실행사는 하위 대행사 실적과 수익 추이가 추가됩니다. 최고관리자는 처리 대기 큐, 누적 충전·집행·지급 포인트·실행사 수익 KPI, 일별 충전 승인액, 상품별 성과, 계정 구성, 집행 상위 캠페인, 운영 기록 타임라인을 봅니다. 참여자는 포인트 지갑, 등급(새싹·잎새·나무·숲), 14일 적립 추이, 참여 가능 미션을 봅니다.
- **캠페인 리포트** — 주문 상세에서 일별 승인·검수·반려 차트, 시간대별 참여, 퀴즈 선택지 분포, 설문 응답(참여자 이름 마스킹), 처리 이력, 정산 요약, 운영 메모를 확인합니다. (`GET /api/report?id=`)
- **주문서** — 상품 카드 선택, 일일 모집 한도, 기간 빠른 선택, 운영 메모, 실시간 견적 요약(집행 기간·하루 평균 필요·주문 후 잔액·한도 부족 경고), 기존 주문 재주문.
- **일일 모집 한도** — 하루 승인·검수 중 제출과 유효 예약 합계가 한도에 이르면 그날 신규 참여를 막습니다. 한도 × 기간이 목표보다 작으면 주문을 받지 않습니다.
- **주문 목록** — 검색, 상품·등록 기간 필터, 상태별 건수, 조회 합계(목표·승인·집행·배정 예산).
- **예산** — 충전 금액 빠른 추가, 부가세 포함 입금 예정액 미리보기, 잔액 내역(거래 후 잔액 표시).
- **운영** — 공지사항(전체·광고 계정·참여자 대상, 상단 고정), 미션 검수 상태·상품 필터와 일괄 승인, 좌측 메뉴 처리 대기 배지, 계정 유형 필터와 잔액 표시.
- **데모 이력** — 데모 모드에서 처음 실행하면 2주치 캠페인·참여·충전 기록과 데모 참여자 180명을 생성해 대시보드를 바로 확인할 수 있습니다. 기존 데모 데이터베이스에도 한 번 추가됩니다.

## 점검 반영 (2026-11-11)

전체 점검 보고서의 항목을 순서대로 반영했습니다.

- **버그 수정** — 실행사 충전 화면에 하위 대행사 충전이 합산되던 문제, 잔액 내역에 다른 캠페인명이 표시되던 문제, 홈의 '내 보상'·'광고 주문' 링크가 계정에 맞지 않던 문제, 충전 대기 금액을 이름으로 찾던 문제.
- **계정** — 참여자·광고주 회원가입(약관 동의), 비밀번호·이름 변경, 임시 비밀번호 변경 안내, 관리자의 이용 정지·해제·비밀번호 재설정·이름·소속 변경, 실행사의 하위 대행사 정지·비밀번호 재설정. 삭제 대신 정지로 거래 기록을 보존합니다.
- **보안·남용 방지** — 같은 아이디로 10번 틀리면 15분간 로그인 제한, 문의는 10분에 5건, 가입은 시간당 5건. 공개 주소 배포 시 Secure 쿠키, 사용 중 세션 자동 연장.
- **관리자** — 미션 검수 페이지 나눔·검색과 일괄 승인 확인창(서버에서 한 번에 처리), 충전·출금 반려 사유, 문의 답변(회원은 프로필의 '내 문의'에서 확인), 공지 수정, 운영 기록 검색, 수익률 상한 30%.
- **광고 계정** — 심사 전 주문 취소·내용 수정, 진행 중 캠페인 일시중지·재개·종료, 충전 신청 취소, 부가세 포함 입금액 저장. 실행사는 하위 대행사 캠페인 리포트를 볼 수 있습니다. 시작 전 캠페인은 빈 차트 대신 안내를 보여 줍니다.
- **참여자** — 참여 남은 시간 카운트다운, 보상 내역에 미션명 표시, 퀴즈 선택지 2~5개, 최소 체류 시간(퀴즈 3초·설문 10초), 같은 글자 반복 설문 답변 차단.
- **출금** — 참여자 포인트(5,000P부터)와 실행사 수익(10,000원부터) 출금 신청 → 최고관리자 지급 완료·반려(반려 시 금액 반환).
- **화면** — 모바일에서 표를 카드형으로 표시, 주문서 하단 고정 견적 바, 상단 종 아이콘은 공지사항(새 공지 표시), Pretendard 글꼴 내장(자주 쓰는 한글 2,350자 부분 글꼴, OFL), 이용약관·개인정보처리방침 화면.
- **성능** — 정적 파일 메모리 캐시·gzip 압축·ETag, 원장·검수·운영 기록은 서버에서 20~30건씩 페이지로 조회.

## 고도화 (2026-11-12)

- **알림 센터** — 충전 승인·반려, 캠페인 심사·운영 중지·종료 정산(반환액 포함), 설문 검수 결과, 출금 지급·반려, 문의 답변, 잔액 조정, 실행사 수익 적립을 계정별 알림으로 보냅니다. 상단과 대시보드 머리글의 종 아이콘에 읽지 않은 수가 표시되고, 열면 공지사항과 함께 보여 줍니다.
- **캠페인 연장·증액** — 진행 중·일시중지 캠페인의 목표 건수, 종료일, 일일 한도를 주문자가 직접 늘릴 수 있습니다. 늘린 건수만큼 예산이 추가 배정되고 종료 시 미집행분은 자동 반환됩니다.
- **CSV 내보내기** — 캠페인 응답 전체(참여자 이름 마스킹), 잔액·수익·포인트 원장, 관리자용 충전·출금·캠페인 목록. 엑셀에서 한글이 깨지지 않도록 BOM을 붙이고, 수식으로 시작하는 응답은 실행되지 않게 처리합니다.
- **관리자 계정 상세** — 가입일, 최근 로그인, 지갑별 잔액, 참여·캠페인·충전 실적, 최근 거래를 계정 관리 창에서 확인하고, 사유를 남겨 잔액을 지급·차감할 수 있습니다(원장·운영 기록·알림에 남음).
- **검수 품질 신호** — 미션 검수 카드에 질문 원문, 답변 글자 수, 같은 캠페인의 동일 답변 수, 참여자의 승인·반려 이력과 가입일을 표시합니다.
- **회원 탈퇴** — 참여자·광고주는 프로필에서 비밀번호와 확인 문구로 탈퇴합니다. 처리 중 출금, 진행 중 캠페인, 남은 광고 잔액이 있으면 막고, 이름·아이디·프로필 이미지·문의 이메일을 지운 뒤 거래 기록은 보관합니다. 탈퇴한 아이디는 다시 가입할 수 있습니다.
- **참여자** — 참여 내역에서 내가 낸 답변을 다시 볼 수 있고, 미션 목록은 참여 중·참여 가능 순으로 정렬합니다. 광고 계정으로 미션을 열면 참여자 계정이 필요하다고 안내합니다.
- **운영·보안** — `/healthz` 상태 확인 주소, HTTPS 배포 시 HSTS, 종료 신호 시 DB 안전 종료, 운영 모드 일일 자동 백업(`data/backups`, 기본 14일 보관), 없는 아이디도 같은 시간이 걸리는 로그인 검사, 처리 대기 출금 3건 제한, 문의 답변 수정 시 기존 답변 불러오기.
- **수정** — 데모 첫 실행 때 충전 내역의 부가세 포함 입금액이 충전액과 같게 나오던 문제.

## 외부 오퍼월 연동 (2026-11-12)

최고관리자가 퀴즈·설문 오퍼 페이지를 만들어 버즈빌·애드팝콘 같은 오퍼월 매체에 공급합니다. 매체 회원이 애즈폼 참여 페이지에서 미션을 마치면 애즈폼이 매체에 완료 포스트백을 보내고, 리워드는 매체가 자기 회원에게 지급합니다.

```
매체 서버 ──(서명된 오퍼 목록 API)──▶ 애즈폼          GET /ow/v1/offers
매체 회원 ──(서명된 랜딩 링크)──────▶ 참여 페이지      /ow/{오퍼 ID}?nw=…&click_id=…&user_id=…&ts=…&sig=…
애즈폼 ────(서명된 완료 포스트백)───▶ 매체 서버        매체가 등록한 https 주소 → 매체가 회원에게 리워드 지급
```

- **관리 화면** — 최고관리자 좌측 메뉴 → 오퍼월 연동. 오퍼 페이지(퀴즈 1~10문항·선택지 2~5개·응시 기회 1~5번, 설문은 검수 후 완료 선택), 공급 매체별 단가·리워드, 목표·일일 한도·기간·최소 체류 시간·같은 IP 하루 참여 한도, 미리보기, 공급 시작·일시중지·종료. 참여·포스트백 탭에서 설문 검수, 포스트백 결과와 재전송. 연동 매체 탭에서 매체 등록·설정·포스트백 테스트·키 재발급. 연동 안내 탭은 매체에 전달할 규격입니다.
- **매체 등록** — 버즈빌·애드팝콘·직접 입력 중에서 고르면 파라미터 기본값이 채워집니다. **기본값은 예시이므로 계약 후 받은 매체 연동 문서에 맞춰 파라미터 이름과 포스트백 주소를 수정하세요.** 등록하면 API 키와 비밀키가 한 번만 표시됩니다.
- **서명** — 오퍼 목록 API: `HMAC-SHA256(비밀키, "{timestamp}\nGET\n{경로}")`, 시각 오차 ±5분, 매체별 허용 IP(선택). 랜딩: `HMAC-SHA256(비밀키, "{오퍼 ID}.{클릭 ID}.{회원 ID}.{ts}")`, ±15분(매체 설정에서 끌 수 있지만 권장하지 않음). 포스트백: `HMAC-SHA256(비밀키, "{transaction_id}.{click_id}.{timestamp}")`를 주소 매크로와 `X-Adsform-Signature` 헤더로 보냅니다.
- **중복·부정 참여 방지** — 같은 클릭 ID는 한 번, 같은 매체 회원은 오퍼당 한 번. 정답·선택지는 매체 피드와 참여 화면 응답에 포함하지 않고 서버에서만 판정. 최소 체류 시간, 랜딩 후 60분 제출 기한, 같은 IP 하루 참여 한도, IP·세션별 요청 제한. 목표·일일 한도는 제출 순간 트랜잭션 안에서 다시 확인하고, 목표에 닿으면 오퍼를 자동 종료합니다. 클릭 ID는 주소창에 남지 않도록 쿠키(HttpOnly·SameSite=Lax·오퍼 경로 한정)로 옮긴 뒤 깨끗한 주소로 이동합니다.
- **포스트백** — 퀴즈는 정답 즉시, 설문은 검수 승인 시 전송. 2xx면 성공, 실패하면 1분·5분·30분·2시간·6시간 뒤 재시도(최대 6회) 후 '전송 실패'로 남기고 관리자가 재전송할 수 있습니다. `transaction_id`는 참여마다 고정이라 매체에서 중복 지급을 거를 수 있습니다. https 주소만 허용하고, DNS 확인 결과까지 검사해 내부망·클라우드 메타데이터 주소로는 보내지 않으며, 리다이렉트를 따라가지 않습니다(SSRF 방지).
- **비밀키 보관** — 매체 비밀키는 AES-256-GCM으로 암호화해 저장합니다. 암호화 키는 `ADSFORM_SECRET_KEY`(운영 권장) 또는 처음 매체를 등록할 때 `data/secret.key`에 만들어지는 파일입니다. **이 키를 잃어버리면 모든 매체 키를 재발급해야 하므로 DB 백업과 따로 보관하세요.**
- **매체용 상태 조회** — `GET /ow/v1/clicks/{클릭 ID}`(오퍼 목록 API와 같은 서명)로 참여·포스트백 상태를 확인할 수 있습니다.

## 공개 주소로 배포할 때

| 환경 변수 | 설명 |
|---|---|
| `ADSFORM_PUBLIC_ORIGIN` | 공개 HTTPS 주소(예: `https://adsform.example`). 설정하면 해당 Host 요청을 받고, 쿠키에 Secure를 붙이며, **테스트 로그인이 기본으로 꺼집니다.** |
| `ADSFORM_HOST` | 서버가 열릴 주소. 기본 `127.0.0.1`. 리버스 프록시가 같은 서버에 있으면 그대로 두면 됩니다. |
| `ADSFORM_TRUST_PROXY` | `1`이면 `X-Forwarded-For`의 **마지막** 주소(리버스 프록시가 덧붙인 값)를 접속 IP로 사용합니다(요청 제한·오퍼월 IP 한도용). 프록시를 한 단계만 두고, 프록시가 접속 IP를 덧붙이도록 설정하세요. |
| `ADSFORM_DEMO` | `1`이면 공개 주소에서도 테스트 로그인을 켭니다. `0`이면 로컬에서도 끕니다. |
| `ADSFORM_ADMIN_PASSWORD` | 테스트 모드가 아닐 때 첫 실행에 한해 `admin` 계정의 비밀번호(12~128자). |
| `ADSFORM_MIN_DWELL` | 미션 최소 체류 시간(초). 지정하면 퀴즈·설문 모두 이 값을 씁니다. |
| `ADSFORM_BACKUP_DAYS` | 자동 백업 보관 일수. 운영 모드 기본 14, 테스트 모드 기본 0(끔). `0`이면 백업하지 않습니다. |
| `ADSFORM_SECRET_KEY` | 오퍼월 매체 비밀키 암호화 키(32바이트, 16진수 64자 또는 base64). 없으면 `data/secret.key`를 만들어 씁니다. 운영에서는 지정을 권장합니다. 생성: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `ADSFORM_OFFERWALL_FRAME_ANCESTORS` | 매체가 참여 페이지를 iframe으로 띄워야 할 때만 허용할 https 출처(공백 구분). 기본은 iframe 차단. |
| `ADSFORM_OFFERWALL_ALLOW_PRIVATE` | `1`이면 로컬 테스트용으로 http·내부망 포스트백 주소를 허용합니다. 공개 주소(`ADSFORM_PUBLIC_ORIGIN`) 설정 시에는 무시됩니다. |

HTTPS 종료는 Nginx·Caddy 같은 리버스 프록시에서 처리하고, 프록시가 원래 Host 헤더를 그대로 넘기도록 설정해 주세요. 상태 확인은 `GET /healthz`(Host 검사 없이 `ok` 응답)를 사용하면 됩니다.

## 운영 범위

충전은 입금 확인 후 수동 승인으로 처리하며 PG 결제는 연결되어 있지 않습니다(PG사 계약 후 연동 필요). 출금은 신청·승인 절차만 있고 실제 송금은 운영자가 직접 처리합니다. 세금계산서 자동 발행과 쿠폰 발급은 연결되어 있지 않습니다. 외부 오퍼월은 연동 구조(피드·랜딩·포스트백)가 준비되어 있고, 매체별 실제 파라미터·포스트백 응답 규격은 계약 후 매체 설정에서 맞춥니다. 이용약관·개인정보처리방침은 기본 문안이므로 오픈 전에 사업자 정보와 법률 검토를 반영해 주세요.

테스트 버튼과 예시 계정을 제외한 별도 로컬 데이터베이스가 필요하면 PowerShell에서 `ADSFORM_DEMO`를 `0`으로 설정합니다. 첫 실행에 한해 `ADSFORM_ADMIN_PASSWORD`로 12~128자의 초기 관리자 비밀번호를 지정합니다. 이 모드의 관리자 아이디는 `admin`이며, 저장 파일은 `data/adsform.sqlite`입니다. 데이터 파일과 초기 비밀번호는 Git에 포함하지 않습니다.

`npm test`로 주문·정산·권한·중복 방지, 회원가입·비밀번호·정지, 취소·출금·일괄 검수, 공개 주소 배포 설정, 알림·잔액 조정·연장·CSV·탈퇴·백업, 오퍼월 서명·중복 방지·포스트백 재시도·설문 검수·IP 한도·키 재발급을 검증할 수 있습니다.
